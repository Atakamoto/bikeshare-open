# Decisions

One line per methodological decision: what you chose, why, and what it changed.
Agents append here via the `/new-feature` skill; you append here by hand.

- Exclude `casual`, `registered`: they sum to `cnt` exactly. Leaky model R^2 1.000 -> honest ridge 0.583.
- Exclude `cnt_2d_bfr`: a shipped 2-day lag we cannot test the alignment of. Build our own lags instead.
- Exclude `instant`, `yr`, `days_since_2011`: time indexes let a tree predict a flat constant past 2011 and a linear model extrapolate a trend we have no grounds for.
- Split 2011 / H1 2012 / H2 2012 by date. Test set touched once, after all feature work.
- Report mean and persistence baselines with every score. Persistence (test R^2 0.510, MAE 840) is within 0.07 R^2 of ridge and beats it on MAE; that caveat goes in the report.
- Add `cnt_roll_14` (mean of the previous 14 calendar days of `cnt`, `.shift(1)` before `.rolling(14)`, so today's count is excluded and every input is known at prediction time). Validation R^2: ridge 0.6475 -> 0.6919 (+0.044), hgb 0.2185 -> 0.1643 (-0.054). Kept because ridge improved by more than 0.01; hgb's drop is consistent with trees failing to extrapolate 2011 levels to 2012. `LAG_WARMUP` raised 7 -> 14, so the training sample fell from 348 to 334 rows; window lengths now live in `LAG_WEEK`/`ROLL_SHORT`/`ROLL_LONG` so the warmup change does not alter `cnt_lag_7` or `cnt_roll_7`.
- Target transformation for HGB: train on the residual `cnt - cnt_lag_1` and predict `cnt_lag_1 + predicted_residual`. Chosen from a controlled, in-memory experiment scored on the validation split only (no test-set scores were inspected). Setup: 334 training rows (2011), 182 validation rows (H1 2012), the existing 15 features from `feature_columns()`, unchanged model hyperparameters, transforms fit on training rows only, and R^2/MAE computed on the original ride-count scale. Validation results: original Ridge R^2 0.6919 / MAE 763.2; persistence 0.4507 / 900.6; original HGB 0.1643 / 1341.2; HGB on `log1p(cnt)` (inverse `expm1`) 0.079 / 1423.1; HGB on residual 0.616 / 823.5; HGB on ratio `cnt / cnt_lag_1` (inverse: multiply by `cnt_lag_1`) 0.544 / 912.1. Why residual: it was the best HGB variant on validation (R^2 +0.452, MAE -517.7 vs original HGB) and the only one to beat persistence on both R^2 and MAE. It helps because a tree can only output values seen in its training targets (original HGB predictions topped out near 5.5k while validation reached 8,362); predicting the change from yesterday anchors every prediction to the current, known demand level, so the model no longer needs to extrapolate the 2011-to-2012 growth. It remains behind Ridge (R^2 0.616 vs 0.6919, MAE 823.5 vs 763.2) because Ridge extrapolates linearly in the lagged-demand features directly, while HGB still approximates the residual with piecewise-constant leaves and under-predicts on average (about -407 rides/day). Why not log1p: it made HGB worse (0.1643 -> 0.079) because a monotone transform does not let a tree predict beyond its training range, so the extrapolation limit remains. Why not ratio: it improved on original HGB but lost to persistence on MAE (912.1 vs 900.6), and the ratio target is heavy-tailed (0.167 to 5.313 in training) and undefined if `cnt_lag_1` is ever 0 (strictly positive in train and validation here, so the check passed). Causal availability: `cnt_lag_1` is the previous day's count, known at the end of day d-1, and is built from `cnt.shift(1)` on the calendar-gap-free index, so the transformed target and its inverse use no day-d information. Caveat: the feature set still contains same-day observed weather (`temp`, `atemp`, `hum`, `windspeed`, `weather_severity`); for true next-day deployment these would have to come from actual weather forecasts, so all scores here, including Ridge and persistence comparisons, assume accurate weather forecasts. This is a single deterministic run on one validation split; the residual model is not yet adopted into `src/train.py`.
